# KRU: окна, инструменты и Discovery — аудит и предложение

Статус: предварительный план для обсуждения, не утверждённая спецификация и не отчёт об исправлении.
Обновление: дальнейшие уточнения пользователя заменяют scope этого предложения. Актуальное направление — `superpowers/specs/2026-09-21-cobblemon-overlays-design.md`: только Cobblemon-аддон, без Packet Inspector/Delay и общего UI Utils; панель боя показывает факты вместо рекомендаций и прогнозов.
Дата: 2026-09-21. В этом проходе проверены исходники и установленный Cobblemon JAR; Minecraft не запускался, рабочие JAR/config не изменялись.

## Границы

- Minecraft 1.21.1, Java 21, официальный внешний Meteor 0.5.8.
- Два независимых аддона: KRU Cobblemon и KRU Tools. Установка одного не требует второго.
- `cobbhelperv2` остаётся источником для чтения. Академические механики задаются выбранным профилем, Academy не становится обязательной зависимостью.
- По текущему запросу нужны план, вопросы и проработка. Реализация и установка — следующие этапы.
- Breeding, Shop, GTS, каталоги и PC Autosort не входят в эту переделку. Экспорт пакетов в файл ранее исключён.

## Что подтверждено кодом

| Часть | Проверенное состояние | Следствие |
| --- | --- | --- |
| UI Utils | `HandledScreenMixin` добавляет обычные Minecraft-кнопки только в `HandledScreen` | PC Cobblemon не получает эту панель |
| PC | В установленном JAR `PCGUI extends Screen`; `closeNormally(true)` отправляет `UnlinkPlayerFromPCPacket` | Нужен Cobblemon-адаптер жизненного цикла и собственных пакетов |
| Desync | KRU вызывает `disableSyncing/enableSyncing` у локального handler | Это не действие upstream: у DupersUnited Desync отправляет server-close, оставляя GUI открытым |
| Delay | `UiUtilsModule.onSend` вызывает `GuiPacketDelay.configure` для каждого пакета; configure заменяет очередь | Следующий пакет теряет ранее накопленную очередь; это функциональный дефект |
| Inspector | Сохраняет `getSimpleName()` и `String.valueOf(packet)`; фильтрует шум по частям имени класса | Полезный decode отсутствует; фильтры ненадёжны на production mappings |
| Inspector UI | Весь список очищается и строится заново каждый tick; подробности выведены прямо в строке | Нет стабильного выбора, ограниченной ширины подробностей и нормального чтения потока |
| Inspector lifecycle | Activate/deactivate очищают буфер; активация меняет `currentScreen` | Просмотр, запись и включение модуля смешаны |
| Type Chart | `TypeChart.onActivate` делает `setScreen(new TypeChartScreen(...))` | Меню PC/боя заменяется отдельной страницей |
| Type Chart arrows | Описание использует Unicode `→`, угол таблицы — `A\\D` | Стрелку стоит рисовать геометрией, с явными подписями атаки/защиты |
| Battle Matchups | `BattleMatchupPanel` читает `messagePane`, вызывает `nativePane.apply` для смены геометрии | Сейчас это встройка в боевой журнал, а не независимая панель |
| Discovery | Reader получает species/shiny/aspects, но observation не сохраняет aspects, уровень, форму, владельца | Часть уже доступных данных теряется до UI |
| Dungeon | Отдельный reader читает уровень/форму/владельца; JSON поддерживает только пять фиксированных targets | Данные частично вынесены, но список категорий, цвета и видимость ещё зашиты в Java |
| Редкость | Есть server/local evidence, но обычный Discovery выставляет rarity только из server evidence | Локальная справочная редкость скрыта за UNKNOWN вместо явного объяснения источника |
| Бинды Meteor | Официальный `Modules.onAction` пропускает бинды модулей, когда открыт Screen | Открытие оверлея внутри PC/боя требует отдельного action-bind, а не только Bind модуля |

## Upstream: что можно перенести фактически

Проверен текущий `DupersUnited/dupersunited-mod` commit
`4b61cea0ca90d4a6e27792a2e7a02598f737b150` (API GitHub и локальная копия совпали).
В `gradle/libs.versions.toml`: Minecraft 1.21.11. В manifest: GPL-3.0-or-later.

- `features/PacketPauseManager.java`: выбор классов C2S, накопление FIFO, ручное возобновление с отправкой очереди.
- `features/GuiPacketDelayManager.java`: отдельное удержание ClickSlot/ButtonClick. Это пауза до release, не настраиваемая задержка в миллисекундах.
- `features/screens/PacketDelayScreen.java`: поиск и выбор Allow/Pause; его взаимодействие можно сохранить при замене оформления на Meteor.
- `features/SaveGuiManager.java`, `events/GuiEvent.java`: сохранение GUI, локальное закрытие/восстановление, Desync, GUI JSON, служебные поля и другие контейнерные действия.
- `features/PacketLogger.java`: форматирование выбранных GUI/inventory/sign событий в чат. Полноценной таблицы инспектора и универсального decoder здесь нет.
- `GuiEvent.shouldAttachToScreen` также не включает PC Cobblemon. Копирование исходника само по себе поддержку PC не даст.

Для порта сохранять upstream-файлы/авторство и точный SHA; отдельно описать каждую адаптацию: API 1.21.1, Meteor lifecycle, принадлежность очереди соединению, лимит, reentry guard, UI. Не называть заново написанный упрощённый класс прямым переносом upstream.

## Варианты подхода

1. **Рекомендуемый:** извлечь нужные компоненты DupersUnited с проверяемым diff, адаптировать к Meteor/1.21.1; строить представления поверх общего контракта панелей. Сохраняет независимость и ограничивает объём backport.
2. Портировать весь DupersUnited и встроить его управление в Meteor. Значительно больше зависимостей, посторонних функций и двух конкурирующих интерфейсов; не соответствует текущей границе двух аддонов.
3. Продолжать собственную реализацию всех инструментов. Проще контролировать API, но расходится с запросом на прямое использование upstream и повторяет риск неполного поведения.

## Предлагаемый интерфейс окон и оверлеев

Содержимое панели отделено от способа показа. Одна рамка, шрифт, масштаб и набор действий в текущей теме Meteor. Обычное окно — для настроек/редактирования; оверлей — для работы рядом с игрой, PC или боем.

- Заголовок для перетаскивания, свернуть, закрыть, закрепить; положение/размер сохраняются, после resize остаются в пределах viewport.
- В PC/бою панель рисуется после исходного экрана, не заменяет его и не меняет геометрию его виджетов.
- Клик/скролл внутри панели потребляет панель; снаружи получает исходный экран. Drag удерживает владельца до release. Ввод поиска не уходит в игру.
- В мире по умолчанию панель пассивна. Предложение: отдельная настраиваемая клавиша временно включает курсор; эта деталь ожидает ответа пользователя.
- Бинды открытия работают внутри PC/боя, но не перехватывают текст при наборе в chat/search/rename. Escape сначала завершает ввод/взаимодействие панели и не закрывает PC тем же нажатием.
- Использовать имеющиеся Fabric screen render/input events, Meteor renderer/widgets. Если конкретный screen обходит стандартный путь, нужен только тонкий hook; бизнес-логика не размещается в mixin.
- Никакого обещания «ноль mixin»: критерий — отсутствие зависимости от внутренней компоновки Cobblemon.
- Общий UI-контракт не должен становиться обязательным третьим runtime-аддоном. При извлечении общего исходного кода предпочтительна сборочная библиотека, упакованная в private namespace каждого JAR. Отдельный ранний тест обязан проверить отсутствие двойного перехвата ввода при обоих аддонах; окончательная упаковка выбирается после этого технического прототипа.

Type Chart сохраняет текущую матрицу и hover/выбор; стрелки рисуются примитивами, подписи явно различают атаку и защиту. Сам chart открывается в оверлее поверх существующего экрана.

Battle Matchups сохраняет read-only reader и проверенные расчёты. Панель справа автоматически появляется при активном бое, сворачивается и перемещается; боевой журнал больше не resize-ится. Завершение боя очищает контекст. Неподдержанный ABI виден как понятный статус.

## Tools и Cobblemon UI

В KRU Tools остаются отдельные Meteor-модули `UI Utils`, `Packet Inspector`, `Packet Delay`. В KRU Cobblemon добавляется `Cobblemon UI Tools` для PC и затем других проверенных custom screens.

У панели инструмента явно отделены: модуль включён, панель открыта, запись/удержание активно. Закрытие окна не очищает запись и не отправляет очередь.

### Packet Inspector

- Одна строка: время, C2S/S2C, читаемый тип или payload/channel, короткое описание.
- Выбор строки фиксирован по ID; справа подробности и Copy. Новый трафик не меняет выбранный пакет.
- Start/Stop recording и Clear раздельны; остановка сохраняет записи до Clear/вытеснения ограниченным буфером.
- Один набор capture-настроек: All/C2S/S2C и Hide movement/keepalive; в viewer только поиск подстроки. При необходимости явный переход в capture-настройки вместо независимой второй копии фильтров.
- Рендерятся только видимые строки. Прокрутка стабильна; автоследование только у конца списка, с явным возвратом Live.
- Upstream summaries используются там, где применимы. Для остальных пакетов потребуется собственное bounded-представление, а не `toString()`.
- Custom payload: identifier/channel и доступные поля. Cobblemon-specific интерпретация принадлежит Cobblemon-части; общему Tools достаточно transport metadata и ограниченного generic просмотра.
- Имя Java-класса и поля могут быть obfuscated: mapping/PacketUtils и typed checks; отсутствие decode показывается явно. Не обещать универсальное восстановление схемы произвольного серверного плагина.
- Нет сохранения пакетов в файл.

### Packet Delay

- Базовое поведение upstream: Hold → FIFO → Release, выбор C2S типов.
- Ранее запрошенный timed delay в ms — отдельный явный режим и документированное дополнение к upstream.
- Счётчик, возраст очереди, Send queued / Drop queued; фильтр payload ID нужен, чтобы не задерживать все custom payload сразу при выборе одного семейства Cobblemon.
- Очередь создаётся один раз на соединение; изменение задержки/фильтра не стирает уже накопленные пакеты.
- Один пакет не попадает одновременно в общую и GUI-очереди. Отправка не перехватывает себя повторно.
- Disconnect/reconnect сбрасывает очередь; старые пакеты никогда не уходят в новое соединение. Политика выключения при ненулевой очереди должна быть видимой в UI, а не скрытым flush.
- При переполнении — явный статус и остановка накопления с определённой политикой; не обходить старую очередь новыми пакетами молча.

### UI Utils и Cobblemon UI Tools

Для vanilla containers переносить выбранные исходные действия с сохранением смысла: Save/Restore, Close local, Desync, Sync ID/Revision, Copy GUI. Остальные upstream-действия (включая fabrication) нужно перечислить в матрице покрытия перед портом, а не объявлять весь UI-Utils поддержанным по четырём кнопкам.

Для каждого Cobblemon screen отдельно проверить доступные действия: локальное закрытие, восстановление текущего session screen, чтение контекста/данных, связанные исходящие payloads. Начать с PC на скриншоте. Нельзя представлять vanilla player inventory handler как handler PC. Нет контейнерного syncId — поле скрыто/помечено неприменимым. Неподдерживаемые действия показывают причину.

Tools не импортирует Cobblemon. Cobblemon UI Tools должен работать и без Tools; дополнительные generic packet controls могут подключаться опционально, но этот мост не должен становиться обязательной зависимостью или второй системой задержки.

## Discovery

Предложение: один сборщик фактов и rule engine в Cobblemon-аддоне, два понятных входа в Meteor:

- `Pokémon Discovery` — готовый поиск и подробные карточки Pokémon.
- `Discovery` — общий просмотр сущностей/блоков/items и редактор правил; `Dungeon`/`Academy` являются профилями, а не Java-категориями.

Первый этап не переносит универсальное ядро в Tools: это потребовало бы нового решения о необязательном provider API между независимыми JAR. Предложение сохраняет текущую продуктовую границу, но делает engine и факты независимыми от Academy.

### Данные Pokémon

- Entity registry ID и species ID — разные поля: общий entity-type недостаточен для определения вида Pokémon.
- Общий snapshot включает доступные species, форму/aspects, уровень, пол, shiny, типы, владельца/wild, entity/Pokémon UUID при доступности, координаты и дистанцию.
- Классы legendary/mythical и т.п. берутся из registry facts; серверные метки вроде radiant определяются выбранным provider/profile.
- Ability/nature/held item/moves/IV/EV показываются только при подтверждённой синхронизации этого источника. Само наличие getter не доказывает реальные данные: client defaults не публикуются как IV противника.
- У значения есть источник и состояние: известно, локальный справочник, не прислано, reader не поддержан. Один недоступный getter не выбрасывает всю карточку.
- Редкость разделена на server spawn bucket, local reference bucket и пользовательскую классификацию. Численный шанс не выводится из названия bucket или неполного локального пула.
- Полный reference/registry enrichment кэшируется; глубокое чтение выбранной карточки выполняется по запросу/изменению, без повторного полного разбора мира каждый кадр.
- Наблюдения относятся к конкретному соединению/миру и загруженным сущностям; выгрузка чанка не выдаётся за исчезновение Pokémon на сервере.

### Правила и редактор

- JSON — одна сохраняемая модель. Meteor editor редактирует эту же модель, а не отдельные дублирующие настройки.
- Произвольные категории: ID, название, enabled, условия, приоритет, цвет, label, boxes/tracer/arrow, дальность.
- Predicate-поля выбираются из схемы доступных фактов; Starscript применяется к labels, как уже сделано.
- Rules list, редактирование условий, preview по выбранной сущности, объяснение Match/No match/Missing fact.
- Inspect crosshair → факты → Create rule: можно создать новую категорию из реально увиденного предмета/entity без правки Java.
- Apply/Save/Reload различимы. Invalid draft не применяется молча и не затирает рабочий файл; UI показывает действующую версию и ошибки. Запись атомарная, миграция v1 с backup.
- Нет профиля: видны observed entities и предложение выбрать/создать профиль. Не «всё включено, но ничего не происходит».
- Профиль Academy поставляется как явно выбранный пример; старые model IDs требуют проверки на текущих видимых фактах.

## Порядок работ и приёмка

1. **Контракт панелей и короткий runtime-прототип.** Type Chart поверх PC, корректные стрелки, отдельный action-bind. Проверить сохранение PC, клики снаружи, drag/release, Escape, масштаб, resize, совместное включение аддонов. Это проверка основы до массового переноса UI.
2. **Battle Matchups на этом контракте.** Отделить reader/calculator от native pane. Сверить существующие расчёты и live бой, показать расположение рядом с журналом.
3. **Upstream Tools.** Таблица покрытия и исходные файлы с SHA/NOTICE, адаптация очереди и GUI lifecycle, Packet Delay как отдельный модуль. Проверки FIFO, серия нескольких пакетов, timed mode, reentry, выключение и reconnect.
4. **Packet Inspector и PC adapter.** Стабильные строки/детали/поиск, Start/Stop/Clear; работа с vanilla chest и custom PC. Запись не пропадает при закрытии панели. Чтение/визуальная проверка в Minecraft отдельно от unit tests.
5. **Discovery facts и Pokémon Discovery.** Объединить readers, проверить supported/unavailable по каждому полю, source-aware rarity, карточки и фильтры.
6. **Общий Discovery editor.** Категория, отсутствующая в Java, создаётся в Meteor, сохраняется в JSON и работает после перезагрузки. Старый Dungeon профиль мигрируется и визуально сравнивается.

После каждого этапа — отдельная проверяемая сборка. Успешная компиляция не заменяет проверку экрана, курсора, PC lifecycle или протокола установленного Cobblemon-форка.

## Решения для обсуждения

1. Поведение курсора у оверлеев: рекомендована закреплённая панель с отдельной клавишей взаимодействия в мире; PC/бой используют уже открытый курсор.
2. Рабочее предложение — два входа `Pokémon Discovery` и `Discovery`, Dungeon как профиль; можно объединить в один модуль с пресетами, но тогда разделение простого поиска и редактора менее явно.
3. Точный список UI Utils определяется матрицей upstream-покрытия; PC — первая обязательная Cobblemon-поверхность, поддержка остальных экранов добавляется по проверенному контракту.
