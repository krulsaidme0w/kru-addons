# Pokémon Discovery и профильный Discovery

Статус: утверждено пользователем 2026-09-22; реализация в работе.
Не отчёт о готовой переделке.

## Продуктовая граница

Minecraft 1.21.1, официальный Meteor 0.5.8, один независимый Cobblemon-аддон.
KRU Tools с Packet Delay остаётся отдельным и не используется Discovery.
Старый cobbhelperv2 — read-only reference. UI Utils, Battle Matchups, Type Chart,
Breeding и PC Autosort в этой работе не переделываются.

Рекомендуемый вариант соответствует предыдущему обсуждению: два входа в Meteor:

- **Pokémon Discovery** вместо нынешнего Discovery: поиск Pokémon, компактная
  лента, фильтры и подробности выбранной наблюдаемой сущности.
- **Discovery** вместо нынешнего Dungeon Discovery: общий инспектор наблюдений,
  произвольные правила и их редактор. Dungeon / Academy — явно выбираемые
  профили, не enum категорий в Java.

Альтернативы: сохранить два нынешних названия — проще миграция, но название
Dungeon вводит в заблуждение для общих правил; объединить всё в один модуль —
меньше входов, но смешивает простой поиск Pokémon с редактором объектов.
Отдельный общий runtime-аддон не создаётся.

## Факты и источники

Единый immutable snapshot для entity / block entity / item / Pokémon providers.
Идентичность: соединение + экземпляр мира + UUID сущности (или позиция блока).
Entity registry ID не подменяет species ID. Живые Minecraft-объекты не попадают
в правила или Starscript. Отсутствующий факт не равен false/0.

Доступные синхронизированные факты Pokémon: species, UUID, форма/aspects,
уровень, пол, shiny, координаты/дистанция, ownership/wild при доказанном API.
Типы и классы из справочника отдельно помечаются registry/reference; не
выдаются за текущие изменённые боевые типы. Getter сам по себе не доказывает
синхронизацию приватных IV/EV, ability, nature, moves, held item или HP.
Такие поля показываются только при подтверждённом клиентском источнике;
иначе конкретное состояние «не прислано» / «reader не поддерживает».

Для каждого факта сохраняется происхождение: live, registry/reference,
server-map, profile. Server bucket, локальный справочный bucket и пользовательская
метка различаются. Нет вычисленного шанса из неполного пула спавна.
CobbleNav 2.2.5 — необязательный адаптер, проверенный на фактическом JAR:
getBucketName / getSpawnDataList / getRenderable. Не отправлять запросы спавна
или команды автоматически. Нет сообщения сервера — нет server rarity.
Radiant/Alpha и другие серверные значения aspects задаются opt-in профилем.

## JSON и правила

Версия 2: профиль содержит произвольные categories и упорядоченные rules.
Категория: стабильный ID, имя, enabled, цвет RGBA, boxes/tracers/nametags/arrows,
максимальная дальность. Правило: ID, enabled, categoryId, priority,
Starscript label, список all-предикатов по типизированной схеме фактов.
Сохраняются equals/min/suffix/contains/token; добавляется max для численных
диапазонов. Произвольный Java/reflection/команды в условиях запрещены.
При одинаковом priority сохраняется порядок правил; первое совпадение выбирает
категорию. Explain показывает результат каждого условия и недоступные факты.

Начальные пределы: 128 KiB, 64 категории, 128 правил, 16 условий на правило.
Ограничения валидируются до применения. Неизвестные поля/категории — ошибка
профиля, не молчаливое игнорирование. Starscript только форматирует snapshot.

JSON и Meteor-редактор используют одну модель. Draft, active и saved различимы:
Validate/Preview не меняют активное состояние; Apply активирует валидный draft;
Save атомарно сохраняет проверенный draft; Reload явно читает файл.
Невалидный draft не затирает активный профиль/файл. Явное переключение на
недоступный другой профиль останавливает старую классификацию и показывает
ошибку — правила прошлого сервера не продолжают работать незаметно.
Пути ограничены каталогом профилей. Перезапись чужого внешнего файла запрещена.

Миграция v1 создаёт пять обычных категорий с прежними цветами/флагами, сохраняет
порядок и смысл правил. Оригинал сохраняется в backup; миграция подтверждается
в редакторе. Исторические Academy model IDs остаются примером до live-проверки.

## Интерфейс

Рабочий инструмент в существующей теме Meteor, без новой визуальной системы.
Компактный список слева, подробности выбранного объекта/правила справа; на
узком viewport подробности открываются отдельной страницей с Back. Длинные
значения обрезаются в строке и доступны в tooltip / Copy, не растягивают окно.

Pokémon Discovery: поиск species, фильтры, сортировка, компактные признаки,
дистанция; подробности выбранного Pokémon по запросу, native portrait при
доступном renderer. Нет огромных постоянно раскрытых карточек.

Discovery: Observations / Rules / Categories / Profile. Прицел → Inspect →
факты → Create rule создаёт draft из реально наблюдаемого объекта. Список
полей показывает тип и наличие значения. Preview объясняет match/no match/
unknown. Без профиля инспектор работает, автоматических подсветок нет;
понятное действие Create / Choose profile вместо пустого включённого модуля.

Поисковый ввод не запускает игровые хоткеи. Оверлей использует существующий
host и Interact Key, захват drag до release, resize/clamp/scale. Положение,
масштаб, свёрнутость и скрытость сохраняются при смене измерения; данные мира
сбрасываются. Discovery не включает глобальный HUD и не переставляет
существующий HUD элемент. Лимит ленты имеет один источник, не скрытые 8 строк.

## Производительность и сохранение поведения

Один общий сбор фактов для двух потребителей; скан распределён по tick budget,
никакой загрузки чанков. Registry enrichment кэшируется. Подробный reader —
для выбранного объекта; рендер читает готовый snapshot без reflection и
полного обхода мира на каждую подпись. Выгрузка чанка убирает live-подсветку,
но не выдаётся за доказанный серверный despawn. Наблюдения не переносятся
между мирами/соединениями. Радиус, лимиты отображения, цвета и типы подсветок
доступны пользователю; технические защитные budgets остаются ограниченными.

Старые настройки двух модулей мигрируются по их прежним стабильным ключам:
discovery → Pokémon Discovery, dungeon-discovery → профильный Discovery.
Переименование отображения не должно включить модули или потерять бинды.

## Порядок и доказательство готовности

1. Единые факты, точный CobbleNav ABI, источники/UNKNOWN, регрессии по аудиту.
2. Pokémon Discovery: карточки, фильтры, HUD lifetime и управляемые параметры.
3. RuleProfile v2, динамические категории, explain, v1 migration и atomic save.
4. Общий Discovery/editor, opt-in Dungeon preset, миграция настроек, интеграция.

Проверки: отсутствие одного getter не теряет остальные факты; отсутствие
ownership не означает wild; данные разных миров не смешиваются; новая категория
работает без правки Java; draft error не портит файл; migration сохраняет
приоритет/результаты старых правил; HUD параметры переживают dimension/rejoin;
быстрый bounded scan и отсутствие per-label world traversal; сборка с
официальным Meteor и актуальными установленными ABI.

Live-проверка отдельно: generic item display/armor stand/block entity,
Pokémon нескольких форм, серверная карта редкости, Dungeon targets,
переход измерения, редактор/drag/ввод/resize. Unit tests и JAR-сборка не
заменяют её. Новый Cobblemon JAR не устанавливается без отдельного запроса.
