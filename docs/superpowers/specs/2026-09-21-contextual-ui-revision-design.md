# KRU: компактные контекстные панели, revision 2

## Основание и статус

Пользователь подтвердил общее UI Utils для инвентаря, серверных контейнерных
меню и отдельного адаптера Cobblemon PC, строку команд Enter/Send, отсутствие
пакетного инспектора/задержек. Подтверждена минималистичная боевая матрица
«известные атаки своих Pokémon × раскрытые противники», только во время боя.
Из предыдущего запроса сохраняются компактный Type Chart, tooltip у курсора
и удаление постоянных верхних/нижних пояснений.

Это спецификация следующего изменения, НЕ описание уже установленного JAR.
Код и установленные моды при подготовке документа не менялись.
Она заменяет противоречащие ей разделы первой спецификации overlays:
facts-only боевую таблицу, исключение общих контейнеров из UI Utils и
постоянную легенду Type Chart.

## Границы

- Minecraft 1.21.1, Java 21, официальный независимый Meteor 0.5.8.
- Изменения внутри `cobblemon-addon`; независимость `tools-addon` сохраняется.
- Общий контейнерный адаптер не импортирует Cobblemon-классы; PC-адаптер
  содержит специфические для Cobblemon операции. Оба обслуживают одну панель
  в существующем Cobblemon-аддоне: дополнительный Tools JAR не требуется.
- Ни Academy, ни названия `/wondertrade`, `/daycare`, `/gts` не являются
  зависимостью или способом распознавания меню. Эти меню покрываются как
  серверные контейнеры, без реализации их торговых/бридинговых механик.
- Не переносим пакетные очереди, инспектор, блокировку пакетов, массовые
  перемещения Pokémon, PC Autosort и автоматизацию серверных команд.
- `../cobbhelperv2` остаётся read-only reference; Meteor и моды сборки не меняем.
- Установка — отдельный явный шаг, а не побочный эффект сборки.

## Выбранная архитектура и альтернативы

Сохраняем общий OverlayHost, стили активной темы Meteor и тонкие input/render
hooks. Добавляем контекстную видимость, tooltip layer и владение текстовым
вводом. Содержание панелей остаётся отдельным от адаптеров данных и действий.

Встраивание кнопок в каждый native screen отвергнуто: разные layouts,
дублирование обработчиков, трудная поддержка PC. Повторное включение старого
Tools UI Utils отвергнуто: он покрывает только HandledScreen, содержит delay
и не даёт нужного единого контракта PC/контейнеров.

## Контекстная видимость

- Включённый модуль означает, что соответствующий инструмент разрешён.
- Battle Matchups видим только при наличии текущего боя; новый battle ID
  автоматически показывает панель. Конец боя очищает данные и скрывает её.
- UI Utils появляется при открытии поддерживаемого контейнера или PC.
  Сам оверлей не открывает, не закрывает и не пересоздаёт native menu.
- Крестик скрывает панель до смены контекста; новый tick сам её не возвращает.
  Хоткей может показать её снова в том же допустимом контексте.
- При закрытии меню UI Utils скрывается. Смена native screen, соединения,
  мира либо handler/PC инвалидирует старый action target.
- Действия повторно проверяют актуальность контекста непосредственно перед
  выполнением, не полагаясь на последний render frame.
- Type Chart остаётся ручной справкой, доступной поверх игры и меню.

## Type Chart

- Новый default scale: 0.8 вместо 1.0; кнопки масштаба остаются.
- Не перезаписывать сохранённый пользовательский масштаб молча. Для уже
  установленного профиля предоставить явный reset к новому default.
- Убрать ATTACK/DEFENCE row, декоративную верхнюю стрелку, нижнюю строку
  выбора и инструкции Hover/Click/Blank. Не оставлять пустые отступы от них.
- Сохранить матрицу 18×18, значения и подсветку строки/столбца.
- Hover показывает tooltip рядом с курсором: полные имена атакующего и
  защищающегося типов и множитель, включая нейтральный 1×. Для заголовка —
  полное имя типа и его роль; A/D поясняется через tooltip.
- Tooltip рисуется поверх панели после содержимого, ограничивается viewport,
  не перехватывает мышь. Геометрия и hit-testing используют один масштаб.
- Фиксация выбора кликом остаётся; Escape сначала снимает фиксацию.

## Battle Matchups

Панель называется Battle Matchups, сохраняет существующий module ID и binds.
Отдельной большой facts/details секции внизу больше нет.

- Строки группируются по собственному Pokémon; в заголовке группы — нативный
  портрет и имя. Внутри только известные атаки, с названием и типом.
- Колонки — раскрытые противники: портрет, имя и доступные типы; текущие
  активные обозначены неброско. Нераскрытые species/moves не угадываются.
- Ячейка содержит справочный множитель эффективности типа атаки против типов
  цели: 0, ¼, ½, 1, 2, 4. Никаких best move, risk, damage, potential и ranking.
- Это именно type chart: способности, предметы, погода и расчёт урона не
  подразумеваются учтёнными. Tooltip явно объясняет ограничение.
- Подтверждённые текущие типы используются первыми. Если известны лишь
  базовые типы раскрытого species/form, показывать справочное значение с `~`
  и tooltip «base types; current battle typing unknown», а не выдавать его
  за текущий факт. При известном изменении типов без известного результата
  base fallback запрещён. Нет достоверной основы — `?`, не 1×.
- Для status move, неизвестного/динамического типа или special move semantics,
  которые обычная таблица типов не выражает, показывать `—`/`?` с причиной,
  а не притворяться, что известен эффект атаки.
- PP/disabled можно показать в hover, но не менять порядок по «выгодности».
- Обновление данных не сбрасывает scroll без смены боя; большие ростеры
  прокручиваются внутри ограниченного окна, не расширяют его на весь экран.
- Native portraits используют существующий guarded renderer и fallback;
  отсутствие ассета не прерывает бой.

## UI Utils

Одна компактная Meteor-панель: строка ввода и Send, ниже действия текущего
экрана. Детальная диагностика не занимает постоянную большую карточку.

- Общий адаптер обслуживает `HandledScreen`, включая инвентарь и серверные
  меню. PC обслуживается отдельным адаптером, а не фиктивным vanilla handler.
- Команда отправляется только явным Enter/Send, ровно один раз. Допускаются
  ввод с `/` и без него; пустая строка не отправляется. Подтверждается лишь
  отправка, не выполнение команды сервером.
- Ввод поддерживает курсор, выделение, вставку, backspace/delete; символы,
  Enter и игровые/модульные hotkeys не проходят в underlying screen, пока
  поле владеет фокусом. Escape сначала снимает фокус ввода.
- Черновик не отправляется при смене меню; disconnect очищает ввод и контекст.
- Обязательные действия: Send, Copy title/context, обычное Close и отдельное
  Close local там, где подтверждена реализация. Close local не называется
  восстановлением доступа/гарантированной серверной сессией.
- PC `closeNormally(false)` и обычное закрытие с unlink различаются явно.
  Vanilla syncId/revision не показываются как свойства PC.
- Не добавлять кнопки-заглушки Desync/Save/Load. В старом локальном коде
  Save/Load сохраняли UUID sets и печатали сообщения, не восстанавливали GUI.
  Настоящее восстановление GUI и protocol-desync требуют отдельно сверенного
  upstream-контракта; их нельзя заявлять реализованными по этим методам.
- Поддержка серверного меню означает работу панели над ним, а не особые права
  на торговлю/размножение и не автоматическое выполнение серверных операций.

## Discovery — отдельный следующий результат, не «уже сделано»

Предыдущие требования не снимаются: Pokemon Discovery с более полными
клиентскими фактами/источниками редкости; общий профильный Discovery с
редактором/preview в Meteor; Dungeon как opt-in preset вместо фиксированных
категорий. Сейчас `PokemonObservation` теряет aspects и не имеет ряда полей,
а `RuleProfile` содержит фиксированный TARGETS. Это реальные незакрытые задачи.
Их спецификация и реализация отделены от переработки контекстных панелей;
завершение этого UI-этапа не считается завершением Discovery.

## Проверки и критерии приёмки

1. Context lifecycle unit tests: вход/выход из боя, закрытие вручную, новый
   battle ID, новый screen/handler, disconnect; без повторного автопоказа.
2. Pure matrix tests: dual types, immunity, unknown, base-reference marker,
   изменённые типы, status/dynamic moves; отсутствие рекомендаций/урона.
3. Input tests: Enter один раз, paste/edit, Escape focus, hotkeys suppressed,
   clicks outside forwarded, drag/release pairing, scaled hit-testing.
4. Tooltip/layout tests: нет старых верхней/нижней полос, маленький viewport,
   правильная строка/колонка после scale/scroll, сохранённый scale не затёрт.
5. Adapter checks по закреплённым MC/Cobblemon ABI; действия проверяют live
   screen и connection на границе вызова, не удерживают устаревшие slots.
6. Полный Gradle test/remapJar и distribution boundary verification.
7. Ручная live-проверка: inventory, `/wondertrade`, `/daycare`, `/gts`, PC,
   начало/конец боя, команда меняет меню, ввод не двигает Pokémon/предметы,
   chart tooltip и оба шрифта Meteor. Unit/build не заменяют эту проверку.
