# KRU Cobblemon: контекстные оверлеи и факты боя

Дата: 2026-09-21.
Основание: пользователь принял направление оверлеев и уточнил scope двумя следующими сообщениями.
Это спецификация поведения, не отчёт о готовности кода. Установленные JAR не менялись.

## Текущий scope

Развиваем только независимый Cobblemon-аддон для официального Meteor 0.5.8, Minecraft 1.21.1 и Java 21.

- Оверлеи Type Chart, Battle Facts и Cobblemon UI Utils.
- Открытие по настраиваемым горячим клавишам, в том числе поверх PC и боя.
- Согласованные перемещение, сворачивание, закрытие и масштаб панелей.
- Pokémon Discovery и общий Discovery с профилем Dungeon остаются в согласованном направлении следующего этапа. Их правила описаны в предыдущем предложении; текущий первый этап посвящён UI Cobblemon.
- Packet Inspector, Packet Delay и общий UI Utils исключены из нового состава. Их перенос из DupersUnited сейчас не выполняется; зависимость Cobblemon-аддона от Tools не появляется.
- Исключение Tools из состава не означает удаление установленного JAR без отдельного шага установки. Исходники отложенных инструментов не удаляются автоматически.
- Academy не обязательна. PC Autosort, Breeding, Shop, GTS и каталоги остаются вне scope.

## Общий контракт панелей

Панель состоит из содержимого, локального состояния показа и общего host-а. Host отвечает за отрисовку, геометрию и владение вводом; конкретный инструмент читает данные через свой адаптер.

- Стиль берётся из активной темы Meteor. Общие заголовок, кнопки, отступы, шрифт, hover, tooltip и clipping.
- В обычной игре панель может оставаться видимой без захвата мыши. Отдельная настраиваемая клавиша включает взаимодействие курсором.
- В PC/бою используется существующий курсор, текущий screen остаётся тем же объектом. Открытие оверлея не вызывает close/reopen исходного меню и не отправляет его пакеты закрытия.
- По умолчанию ни одна клавиша не конфликтует с существующими биндами: actions настраиваются в Meteor. Один модульный Bind не заменяет действия открытия/фокуса, поскольку Meteor пропускает его при открытом Screen.
- Поиск, чат, переименование и другой текстовый ввод имеют приоритет над overlay hotkeys.
- Клик/scroll внутри панели получает верхняя панель; снаружи — исходный экран. Drag сохраняет владельца до release. Нажатие и отпускание не расходятся между панелью и PC.
- Escape снимает фокус/закрывает верхнюю активную панель, не закрывая исходный экран тем же событием.
- Положение сохраняется. Resize окна игры/смена GUI scale пересчитывает bounds, чтобы заголовок не оказался за пределами viewport.
- Основа hook-ов — Fabric screen render/input events и штатные Meteor-компоненты. Для нестандартного screen допустим тонкий мост. Логика данных и действий не помещается в mixin.

## Размер окна

Первое решение — кнопки уменьшения, увеличения и Reset в заголовке плюс настройка масштаба в Meteor. Масштабируется вся панель вместе с содержимым, а hit-testing использует обратное преобразование.

Это обеспечивает уменьшение/увеличение без отдельной сложной системы растягивания колонок. Максимальный размер ограничен viewport; при минимальном читаемом размере используется прокрутка содержимого. Хранить выбранный пользователем масштаб отдельно от временного fit-to-viewport, чтобы окно возвращалось к нему при увеличении экрана игры. Перетаскивание угла для произвольной ширины/высоты не является требованием первого этапа.

## Type Chart

Сохраняем текущую матрицу 18 типов, значения, hover и фиксацию выбора. Панель доступна из мира, PC и других поддерживаемых экранов.

Стрелки рисуются геометрией/иконками, а не Unicode-глифами, пропадающими в выбранном шрифте. Явные подписи атаки и защиты; одна непротиворечивая легенда. Не менять правила эффективности типов под видом UI-правки.

## Battle Facts: новое содержание бывшего Battle Matchups

Пользователь просит фактическую статистику боя и таблицу в стиле чарта с изображениями из Cobblemon. Больше не строить оценку выгодной пары, прогноз ответа или рекомендацию хода.

### Подтверждённая проблема прежнего расчёта

В `MatchupCalculator` существуют `best`, `Potential`, `potentialDominates`, `risk`, строки Hit/Reply/Potential и эвристические предупреждения. Даже когда расчёт использует известные типы, выбор «лучшего» и потенциальной атаки — дополнительная интерпретация. Эти результаты исключаются из нового presentation path, вместе с рекомендательными стрелками и цветом «выгодно/опасно».

### Представление

- Рабочее имя модуля/панели — `Battle Facts`; старый keybind/enabled state нужно мигрировать при переименовании, если сохранение настроек это позволяет.
- Колонки — известные Pokémon, сгруппированные по сторонам боя. В шапке портрет/sprite из Cobblemon и имя; активные и выбывшие обозначены явно.
- Строки — уровень, известные текущие типы, HP, статус, подтверждённые изменения боевого состояния. Подробная карточка по клику показывает раскрытые атаки, способность/предмет и источник/актуальность данных.
- Раскрытые сведения противника сохраняют пометку последнего наблюдения; неизвестные слоты не получают предполагаемые виды и наборы атак.
- Собственные точные HP и противнический отображаемый процент различаются. Не восстанавливать точные HP/статы противника из процента и уровня.
- При подтверждённых boosts показывать стадии, например `Atk +1`, а не предполагаемую итоговую характеристику. Если текущий reader не получает boosts, показывать недоступность, а не ноль.
- Погода, terrain, screens, счётчик хода и другие условия допустимы только при наличии соответствующего факта в клиентском боевом состоянии. Таймер не угадывать из типичной длительности эффекта.
- Иконки типов, статусов и предметов использовать из доступных ресурсов мода. Портрет при неподдержанной модели имеет нейтральный fallback; падение renderer не должно срывать бой.
- Цвет показывает тип/статус/HP, но не советует «лучший выбор».
- Изменение размера, сворачивание и перемещение работают как у Type Chart. По умолчанию панель размещается справа; боевой журнал не меняет размер.
- При смене/завершении боя контекст сбрасывается, данные одного боя не переносятся в другой.

### Граница справочных расчётов

Базовый вариант Battle Facts содержит только сообщённые/наблюдавшиеся факты. Множители типов остаются в отдельном Type Chart. Если пользователь захочет их внутри боевой панели, это отдельный ясно подписанный справочный раздел, а не прогноз урона и не оценка выбора Pokémon.

## Cobblemon UI Utils

Модуль находится в Cobblemon-аддоне, панель использует тот же host. В этой версии нет кнопок записи, задержки, блокировки и ручной отправки очереди пакетов.

- Начальная обязательная поверхность — PC; затем summary/party и другие Pokémon-экраны по подтверждённому контракту адаптера.
- Безопасные read-only действия: определить экран, показать его доступные данные, скопировать сведения о выбранном Pokémon/контексте; открыть Type Chart.
- UI Utils-действия Save/Restore, Close local и Desync должны быть проверены отдельно для соответствующего Cobblemon screen. Desync означает конкретное действие протокола, а не произвольный вызов vanilla handler.
- PC в установленном форке наследует Screen, а `closeNormally(true)` отправляет `UnlinkPlayerFromPCPacket`. Нельзя показывать inventory `syncId/revision` как состояние PC.
- Сохранённый GUI принадлежит текущему соединению и контексту PC. После disconnect/world replacement его нельзя восстановить как действующую серверную сессию. Восстановление окна не является подтверждением восстановления доступа на сервере.
- Неподдерживаемое действие отображает причину недоступности. Обычные открытия оверлеев никогда не отправляют протокольные действия.

## Последовательность и проверяемый результат

1. Host, маршрутизация ввода, hotkeys, перемещение, сворачивание и масштаб. Первая панель — существующий Type Chart с исправленными стрелками.
2. Battle Facts: отдельная read-only модель представления, портреты и таблица. Исключить расчёт best/risk/potential из активного пути, отвязать от native message pane.
3. Cobblemon UI Utils: PC adapter и корректные действия по его lifecycle. Проверить PC, summary/party отдельно; не объявлять покрытие всех экранов по одной успешной проверке.
4. Продолжить согласованную переделку Pokémon Discovery и профильного Discovery отдельным этапом после проверки общего UI.

Unit/integration проверки: преобразование координат и hit-regions при масштабировании; overlay input ownership; неизвестные и устаревшие battle facts; reset на новый бой/соединение; отсутствие рекомендаций и выдуманных значений.

Runtime приёмка: chart открыт поверх PC без закрытия/пакетов закрытия; клик снаружи работает в PC, внутри не перекладывает Pokémon; Escape и drag-release корректны; горячая клавиша не срабатывает при вводе текста; масштаб после resize остаётся рабочим; battle panel не изменяет журнал и показывает только доступные факты. Сборка и unit tests не доказывают эти runtime-пункты.
